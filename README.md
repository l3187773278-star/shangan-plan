# 上岸计划 · 通用备考版

> 一个**零依赖**的多考试备考助手（PWA）。首次打开走三步配置向导，自动生成备考阶段、关键节点和起步任务；
> 之后负责倒计时、每日打卡、番茄钟、间隔重复复习与学习统计。数据只存在你自己的浏览器里。

支持考试类型：考研 / 专升本 / 高考 / 四六级 / 公务员 / 教师资格 / 雅思托福 / 自定义。

---

## 功能

| 模块 | 说明 |
|---|---|
| 配置向导 | 选考试类型 → 填学校与考试日期 → 定科目与每日记忆目标，自动生成「阶段路线 + 关键节点 + 前三天起步任务」 |
| 今日 | 考试倒计时、整体进度、打卡、今日任务、保底三件套（再忙不断线）、记忆目标、到期复习卡片 |
| 计划 | 按天排任务（科目自选）、本周概览 |
| 专注 | 番茄钟，按科目累计时长，完成有提示音，刷新不丢计时 |
| 复习 | 间隔重复闪卡（SM-2 遗忘曲线）+ 随机闭卷自测；答错的卡片当天重新出现，并自动提高难度 |
| AI 出题 | 接入 DeepSeek：按科目与范围出题、批改要点，可一键收进卡片库或错题本（需自填 API Key） |
| 笔记 / 错题 | 四行法笔记模板、错题掌握度标记 |
| 统计 | 专注分钟、任务完成率、复习量图表，科目分布，连续打卡天数 |
| 换设备 | 导出 JSON 备份 / 导入恢复；电脑与手机在同一 WiFi 下自动双向合并同步 |

## 怎么运行

### 电脑

```bash
npm start          # 等价于 node serve.js，会自动打开浏览器
```

也可以不起服务，直接双击 `index.html`——功能都在，只是没有离线缓存和局域网同步。

### 手机

**方式 A：同一 WiFi（零部署）**

1. 电脑执行 `npm start`（或双击 `启动.bat`）；
2. 启动窗口里会显示形如 `http://192.168.x.x:4000` 的手机访问地址；
3. 手机连同一个 WiFi，用浏览器打开该地址。

> 打不开多半是防火墙：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 勾选 **Node.js JavaScript Runtime** 的「专用网络」。

**方式 B：部署到 GitHub Pages / Netlify / Cloudflare Pages**

把仓库根目录当静态站点发布即可（纯前端，无需构建）。手机浏览器打开后选「添加到主屏幕」，就能像 App 一样全屏使用，并支持离线。

### 数据与备份

- 全部数据存在浏览器 `localStorage`，**不上传任何服务器**，无账号、无埋点；
- 换设备：`更多 → 设置与备份 → 导出备份`，在新设备导入；
- 清除浏览器数据会清掉记录，建议定期导出。

## 工程结构

```
.
├─ index.html      界面骨架（单页，四个视图：今日 / 计划 / 复习 / 更多）
├─ core.js         核心纯逻辑层：日期、SM-2、多端合并、去重、连续打卡
├─ app.js          界面与状态：渲染、事件、番茄钟、同步调度
├─ styles.css      样式（含响应式与打印样式）
├─ serve.js        本地服务：静态托管 + HTTP Range/ETag + api/sync + DeepSeek 转发
├─ sw.js           Service Worker：网络优先、离线回退
├─ manifest.json   PWA 清单
└─ test/           自动化测试（Node 内置 test runner，零依赖）
```

### 为什么要单独抽 `core.js`

算法写错时通常**不报错**，而是「数据悄悄丢失」——复习间隔算错、两端同步把记录吃掉、任务被重复生成。
所以把这些函数集中到一层**不碰 DOM、不碰 localStorage、不依赖系统时间**的纯函数里：

- 浏览器：`<script src="core.js">` 挂到 `window.SGCore`；
- Node 测试：`require('./core.js')`。

同一份文件两种用法，**没有构建步骤，也没有第二份实现**——避免两边慢慢跑偏。

## 测试

```bash
npm test          # node --test test/
npm run check     # 四个 js 文件的语法检查
```

覆盖范围（35 条用例）：

- **SM-2 间隔重复**：间隔 1 → 6 → 间隔×难度系数的增长、答错重置与当天重排、难度系数下限 1.3、评分 3/2 的通过边界、旧卡片缺字段时的安全升级；
- **多端合并**：以较新一端为底且不丢另一端记录、同 id 冲突取向、反复合并幂等、每日打卡「任一为真即真」、复习记录去重；
- **日期**：跨月/跨年/闰年加减、天数差、夏令时下的稳定性；
- **数据清理**：任务按「日期|科目|标题」去重并优先保留已完成、卡片按「科目|问题」去重；
- **统计**：连续打卡（今天没打卡从昨天起算）、累计打卡、某日专注时长；
- **接线契约**：`app.js` 里每个 `CORE.*` 都真实存在、`index.html` 先加载 `core.js`、`sw.js` 缓存清单包含 `core.js`、SM-2 公式没有第二份实现。

## 技术要点

- **零依赖**：没有框架、没有打包器、没有运行时依赖；`npm install` 一个包都不装，测试用 Node 18+ 内置的 `node:test`。
- **离线优先**：Service Worker 网络优先 + 缓存回退，断网仍可打卡复习。
- **本地服务**：`serve.js` 只用 Node 内置模块，支持 `HTTP Range`（大文件拖动播放）、`ETag`/304 协商缓存、内存缓存，并作为 DeepSeek API 的反向代理绕过浏览器 CORS。
- **双端同步**：电脑端服务把数据落到 `_sync-data.json`，两端按 id 求并集、按 `savedAt` 决定基底，几秒内自动合并。
- **数据不出本机**：AI 出题的 Key 只存本地，请求由本机服务转发。

## 浏览器支持

Chrome / Edge / Safari 的现代版本（需要使用 `fetch`、`Service Worker`、CSS 变量）。IE 不支持。
