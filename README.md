# 上岸计划 · 通用备考版

> 一个**零依赖、零构建**的多考试备考助手（PWA）。首次打开走三步配置向导，自动生成备考阶段、关键节点与起步任务；
> 之后负责倒计时、每日打卡、番茄钟、间隔重复复习与学习统计。数据只存在你自己的浏览器里。

支持考试类型：考研 / 专升本 / 高考 / 四六级 / 公务员 / 教师资格 / 雅思托福 / 自定义。

---

## 功能

| 模块 | 说明 |
|---|---|
| 配置向导 | 选考试类型 → 填学校与考试日期 → 定科目与每日记忆目标，自动生成「阶段路线 + 关键节点 + 前三天起步任务」 |
| 今日 | 考试倒计时、整体进度、打卡、今日任务（按科目分组）、保底三件套、记忆目标、到期复习卡片 |
| 计划 | 按天排任务、本周概览（周一开头，完成度一眼可见） |
| 专注 | 番茄钟：按科目累计时长、完成有提示音、**刷新页面不丢计时**（按时间戳补偿流逝） |
| 复习 | 间隔重复闪卡（SM-2）+ 随机闭卷自测；答错的卡片当天重新出现，并自动提高难度 |
| AI 出题 | 接入 DeepSeek：按科目与范围出题、批改要点，可一键收进卡片库或错题本（需自填 API Key） |
| 笔记 / 错题 | 四行法笔记模板、长文阅读浮层、错题掌握度标记 |
| 统计 | 专注分钟 / 任务完成率 / 复习量三张 7 天图表，科目分布，连续打卡 |
| 换设备 | 导出 JSON 备份 / 导入恢复；电脑与手机在同一 WiFi 下自动双向合并同步 |

## 怎么运行

### 电脑（推荐）

```bash
npm start          # 等价于 node serve.js，会启动本地服务并自动打开浏览器
```

Windows 上也可以直接双击 **`启动.bat`**（内部同样是 `node serve.js`）。

> **请务必用本地服务打开，不要双击 `index.html`。**
> 用 `file://` 直接打开时，部分浏览器会禁止本页写入 localStorage，
> 表现为「加了任务、刷新就没了」。真的用文件方式打开时，应用会在启动时弹窗提示你改用 `启动.bat`。

### 手机

**方式 A：同一 WiFi（零部署）**

1. 电脑执行 `npm start`（或双击 `启动.bat`）；
2. 启动窗口里会显示形如 `http://192.168.x.x:4000` 的手机访问地址；
3. 手机连同一个 WiFi，用浏览器打开该地址。

> 打不开多半是防火墙：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 勾选 **Node.js JavaScript Runtime** 的「专用网络」。

**方式 B：部署到 GitHub Pages / Netlify / Cloudflare Pages**

把仓库根目录当静态站点发布即可（纯前端，无需构建步骤）。手机浏览器打开后选「添加到主屏幕」，就能像 App 一样全屏使用，并支持离线。

> 注意：部署到公网后「电脑 ↔ 手机局域网同步」不可用（它依赖本机 `serve.js`），其余功能与数据持久化都正常。

### 数据与备份

- 全部数据存在浏览器 `localStorage`，**不上传任何服务器**，无账号、无埋点；
- 换设备：`更多 → 设置与备份 → 导出备份`，在新设备导入；
- 清除浏览器数据会清掉记录，建议定期导出。

## 工程结构

```
.
├─ index.html        单页骨架（四个主视图 + 若干子页）
├─ core.js           纯逻辑层：日期、SM-2、多端合并、去重、连续打卡（无 DOM、可单测）
├─ js/
│  ├─ bus.js         模块通信：几十行的发布订阅，解开「数据层↔页面层」的循环依赖
│  ├─ exams.js       八种考试的模板数据（纯数据，无逻辑）
│  ├─ ui.js          UI 基础层：格式化、DOM 简写、toast、模态框、科目配色
│  ├─ data.js        状态中枢：唯一持有数据、唯一读写 localStorage、所有增删改 + 同步
│  ├─ timer.js       番茄钟：运行态持久化与跨刷新恢复
│  ├─ views.js       页面层：各视图渲染、表单弹窗、AI 出题交互
│  └─ boot.js        启动与事件接线：唯一的入口，所有按钮动作在此分发
├─ styles.css        样式（含响应式与打印样式）
├─ serve.js          本地服务：静态托管 + Range/ETag/预压缩 + api/sync + DeepSeek 转发
├─ sw.js             Service Worker：网络优先、离线回退
├─ manifest.json     PWA 清单
└─ test/             自动化测试（Node 内置 runner，零依赖）
```

### 三个刻意的取舍

1. **算法单独一层（`core.js`）**：这些函数出错时不会抛异常，而是「数据悄悄丢失或错乱」——
   所以它们不碰 DOM、不碰 `localStorage`、不读系统时间（时间可注入），因此能在 Node 里逐条断言。
2. **用事件而不是直接调用解耦**：数据改完只 `emit('change')`，由 `boot.js` 订阅后统一重渲染。
   否则 `data.js` 就得反过来依赖页面层，拆模块就白拆了。
3. **`state` 用 getter 暴露**：导入备份、同步合并、清空数据都会整体替换状态对象，
   getter 保证任何模块拿到的都是最新那份引用，不会读到过期副本。

## 测试

```bash
npm test          # node --test test/  →  50 条用例
npm run check     # 全部脚本的语法检查
npm run lint      # ESLint（需先 npm install）
npm run format    # Prettier（需先 npm install）
```

测试全部零依赖，用 Node 18+ 内置的 `node:test`。

**算法与数据（`test/core.test.js`，27 条）**

- SM-2：间隔 1 → 6 → 间隔×难度系数的增长顺序、答错重置与当天重排、难度系数下限 1.3、评分 3/2 的通过边界、旧卡片缺字段时的安全升级；
- 多端合并：以较新一端为底且不丢另一端记录、同 id 冲突取向、反复合并幂等、每日打卡「任一为真即真」、复习记录去重；
- 日期：跨月/跨年/闰年加减、天数差、夏令时下稳定；
- 数据清理：任务按「日期|科目|标题」去重并优先保留已完成、卡片按「科目|问题」去重；
- 统计：连续打卡（今天没打卡从昨天起算）、累计打卡、某日专注时长。

**接线契约（`test/contract.test.js`，12 条）**

拆模块最容易断的不是算法而是接线，所以这些也被断言覆盖：

- 代码里引用的每个 `#id` 都真实存在（HTML 静态声明或 JS 动态生成）；
- 每个 `data-action` 都有对应的分发分支（防止按钮点了没反应）；
- `index.html` 的脚本加载顺序符合依赖，`sw.js` 缓存清单覆盖全部脚本；
- 各模块挂载的 `SG.*` 命名空间与调用方一致，`boot.js` 调用的成员确实被导出；
- SM-2 公式只存在一份，`core.js` 不含 DOM/存储依赖。

**启动冒烟（`test/boot.test.js`，11 条）**

在没有浏览器的环境里真跑一遍启动：用最小假 DOM 依次执行 8 个脚本，断言

- 全部脚本能加载执行完（白屏类问题会被这条直接抓住，并指出是哪个文件哪一行）；
- 启动过程不写 `console.error`/`console.warn`；
- 十余个关键容器**确实被写入了内容**（不只是「没报错」），逐个视图切换都不抛错；
- 模拟点击能走到数据层并落盘；番茄钟能启停；存储不可用时会弹窗而不是静默丢数据。

## 技术要点

- **零依赖、零构建**：没有框架、没有打包器；`npm install` 一个包都不装（只在你跑 lint/format 时才需要 devDependencies）。
- **离线优先**：Service Worker 网络优先 + 缓存回退，断网仍可打卡复习。
- **本地服务**：`serve.js` 只用 Node 内置模块，支持 `HTTP Range`（大文件拖动）、`ETag`/304 协商缓存、预压缩（`.gz`），并作为 DeepSeek API 的反向代理绕过浏览器 CORS。
- **双端同步**：电脑端把数据落到 `_sync-data.json`，两端按 id 求并集、按 `savedAt` 决定基底；合并只增不减，避免「一端删掉又被另一端同步回来」。
- **数据不出本机**：AI 出题的 Key 只存本地，请求由本机服务转发。

## 浏览器支持

Chrome / Edge / Safari 的现代版本（需要 `fetch`、`Service Worker`、CSS 变量）。IE 不支持。
